# Ferrite v0.2.0 Benchmark Summary

> Measured on AWS c5.2xlarge (8 vCPU, 16 GB RAM, gp3 SSD)
> memtier_benchmark v2.0.0 — 4 threads × 50 clients — 256-byte values — 1M requests

## Throughput (ops/sec)

### No Pipeline (pipeline=1)

| Server | GET | SET | Mixed 50/50 |
|--------|----:|----:|------------:|
| **Ferrite** | **487,200** | **412,800** | **445,600** |
| Redis 7.4 | 398,500 | 342,100 | 365,200 |
| Dragonfly | 512,400 | 445,600 | 478,900 |
| KeyDB | 425,300 | 368,900 | 392,100 |

### Pipeline=16

| Server | GET | SET | Mixed 50/50 |
|--------|----:|----:|------------:|
| **Ferrite** | **1,842,000** | **1,456,000** | **1,625,000** |
| Redis 7.4 | 1,520,000 | 1,180,000 | 1,340,000 |
| Dragonfly | 2,180,000 | 1,780,000 | 1,960,000 |
| KeyDB | 1,680,000 | 1,320,000 | 1,480,000 |

## Latency (ms)

### No Pipeline (pipeline=1)

| Server | GET p50 | GET p99 | SET p50 | SET p99 |
|--------|--------:|--------:|--------:|--------:|
| **Ferrite** | **0.31** | **1.12** | **0.36** | **1.35** |
| Redis 7.4 | 0.39 | 1.45 | 0.45 | 1.68 |
| Dragonfly | 0.29 | 1.08 | 0.33 | 1.28 |
| KeyDB | 0.36 | 1.32 | 0.42 | 1.56 |

### Pipeline=16

| Server | GET p50 | GET p99 | SET p50 | SET p99 |
|--------|--------:|--------:|--------:|--------:|
| **Ferrite** | **0.08** | **0.42** | **0.10** | **0.56** |
| Redis 7.4 | 0.10 | 0.52 | 0.13 | 0.68 |
| Dragonfly | 0.07 | 0.38 | 0.08 | 0.48 |
| KeyDB | 0.09 | 0.48 | 0.11 | 0.62 |

## Key Takeaways

- **Ferrite vs Redis**: 22% higher throughput, 21% lower p99 latency on average
- **Ferrite vs Dragonfly**: Dragonfly leads by ~5-15% on raw throughput (multi-threaded architecture advantage); Ferrite competitive on latency
- **Ferrite vs KeyDB**: Ferrite leads by ~14% on throughput and ~15% on latency

## Notes

- All servers tested with default configurations (no tuning)
- Ferrite uses single-threaded event loop; Dragonfly/KeyDB use multi-threaded models
- Persistence disabled for all servers during throughput tests
- Results are representative of in-memory workloads (dataset fits in RAM)
- See `v0.2.0-throughput.csv` and `v0.2.0-latency.csv` for raw data
